# M4 tailoring implementation

M3 was approved and pushed at `4a80735`. Only explicit selections enter tailoring. The coordinator owns the schema, durable queue, lease fencing, checkpoints and integration. Immutable revision rows hold editable source and PDF bytes. The latest complete KB and JD are captured at claim time. A persisted plan listing every project and exactly five selected IDs precedes track selection and template rendering. Retry uses the same frozen input and successful checkpoints. Failed verification keeps the attempt out of Pending submission.

Shared types are in `src/lib/tailoring/contracts.ts`. The workflow agent owns `src/lib/tailoring/workflow.ts`, related tests and the fixed internal Codex task integration. It exports `planProjects(input, signal): Promise<SelectionPlan>`, `editResume(input, plan, signal): Promise<TailoredContent>`, and `reviewResume(input, plan, content, documents, signal): Promise<ReviewResult>` using the shared types. The reviewer receives the actual PDF text. Preserve protected fields and tie generated claims to validated sources. Use V5 policies without copying personal data.

The rendering agent owns `src/lib/tailoring/render.ts`, its tests and worker rendering modules. It exports `renderTailoring(content: TailoredContent, theme: Record<string, unknown> | null, signal: AbortSignal): Promise<RenderedDocument[]>`. Validate structured input, render registered LaTeX or frozen HTML theme, inspect current PDF, layout and links. Keep artifact directories isolated. Both worker feature owners register handlers in separate modules. The coordinator alone edits worker/server.ts and calls each handler after token authentication. Each exports `handleTailoringAI` or `handleTailoringRender` with signature `(request: IncomingMessage, response: ServerResponse): Promise<boolean>`. Return false for unmatched routes. Keep these endpoints outside the public execution proxy.

The product agent owns the /tailoring screen, server actions, document downloads, nav, discovery waiting-list link, and associated tests. The coordinator exports `loadQueue(): Promise<QueueView>`, `pauseQueue(paused: boolean)`, `moveRun(id: string, direction: -1|1)`, `removeRun(id: string)`, `cancelRun(id: string)`, `retryRun(id: string)` from `src/lib/tailoring/queue.ts`. Document route reads TailoringRevision fields id, kind, format, source, pdf, preview, verification, evidence, text and matchReport. All reads and mutations require authentication. The queue starts enabled. Reordering and removal apply to waiting items, and cancellation also works during execution. Each milestone ends at local review.
